# 荒野行動 チーム適性診断 / SQUAD FIT

スマホ向け、外部依存のない静的HTML/CSS/JavaScriptの診断サイトです。
サーバー処理、DB、API、アクセス解析、外部フォントは使いません。

## 使い方

`index.html` をブラウザで開くだけで利用できます。GitHub Pagesではフォルダの内容をそのまま公開できます。インストールやビルドは不要です。

- 基本22問、回答に応じた追加確認を最大3問（合計22〜25問）
- 12能力、7役割、6武器カテゴリを5段階評価。不足する根拠は「不明」
- 第一・第二役割候補、得意・不得意、武器構成、交戦距離、6段階の立ち回り、味方への説明
- 結果コピー。クリップボードが使えない環境では選択可能なテキストを表示
- 前の質問、回答見直し、途中診断と再開、やり直し
- 回答と任意のプレイヤー名はページ内のメモリだけに保持。外部送信・永続保存なし

ページの再読み込み・終了で回答は消えます。結果テキストを先にコピーしてください。

## 診断ロジック

元の「荒野行動 チーム適性診断GPT」の評価軸と方針を、選択式のルールとして実装しています。元の会話に完成した数式はなかったため、設問の一部・配点・重みは今回の実装用に設計した初期仮説です。科学的な能力測定・実戦データで検証された尺度ではありません。

### 能力の評価

各回答は関連する能力に1〜5の観測値を加え、独立した設問の加重平均を四捨五入します。現在の設問の重みはすべて1です。好みだけを聞く冒頭の質問は無加点で、役割の直接判定には使いません。

- 独立した根拠が2件未満：不明
- 「得意」という自己申告：最大4の観測値
- 評価5：平均を丸めて5、かつ5を支持する独立回答2件以上、矛盾なし
- 評価1：平均を丸めて1、かつ1を支持する独立回答2件以上、矛盾なし
- 2以下と4以上の回答が同じ能力に混在：回答に幅あり、暫定評価
- 未回答・「分からない」・未経験：0点として計算せず、根拠から除外

「1＝明確な弱点、2＝補完が必要、3＝標準、4＝得意、5＝明確な強み」。他プレイヤーとの偏差値・ランキングではありません。

### 追加確認と回答変更

22問が終わると、次の順で最大3問を選びます。

1. 近距離が苦手なら原因確認
2. 静止敵へのSRが得意なら、撃ち直しの精度と射線確認
3. 回答が矛盾している能力を1つ確認
4. 近距離の原因が照準なら、通過・手前・初動遅れを確認
5. 残り枠で根拠の少ない能力を確認

3問で解消しなかった不足・矛盾は結果に残します。分岐を無限に増やしません。
前の回答を変更した場合、その先の回答を削除して分岐を計算し直します。条件から外れた追加質問を採点に混ぜません。
5回答以降は途中診断ができ、未回答の部分は不明にします。

### 役割と武器

能力評価のあとで、`data.js` にある重みから適性を算出します。
主要能力が不明、または必要な能力の重みの75%未満しか分からない場合は保留。
主要能力の最低値が2以下なら「最低値＋1」を適性上限とし、他能力で弱点が隠れないようにします。
適性5は主要能力がすべて4以上で、うち2つ以上が5の場合に限ります。

評価3以上の役割を第一・第二候補にします。差が0.3以内なら複数適性と表示し、強く断定しません。
武器構成は評価3以上のARと補助武器の組み合わせです。候補が不足する場合は保留・条件付きにします。

最新の具体的な銃名・数値・ランキングは含めません。好みや武器調整の影響を断定せず、カテゴリ適性を提示します。

### 今回の範囲

個人診断を実装しています。元のGPTにある自由回答の意味解釈、戦績画像解析、複数人の自動編成は含めません。結果をコピーしてチーム内で比較できます。

## ローカル確認

通常は `index.html` を直接開けます。HTTPで確認する場合は、このフォルダで次を実行します（開発時だけのサーバーです）。

```sh
python3 -m http.server 4173
```

ブラウザで `http://localhost:4173` を開きます。終了は Ctrl+C。

テストは Node.js がある環境で実行できます。サイトの利用にNode.jsは不要です。

```sh
node tests/engine.test.cjs
```

## GitHub Pagesへ公開する場合

1. GitHubで公開用のリポジトリを作成。
2. このフォルダの中身を `main` ブランチの直下に配置。
3. Settings → Pages → Build and deployment を開く。
4. Sourceを **Deploy from a branch**、Branchを **main**、フォルダを **/(root)** に設定して保存。
5. 表示される公開URLへアクセス。

相対パスを使っているため、`https://ユーザー名.github.io/リポジトリ名/` でも利用できます。
更新はファイルを編集して同じブランチへpushすると反映されます。

[GitHub公式：公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
